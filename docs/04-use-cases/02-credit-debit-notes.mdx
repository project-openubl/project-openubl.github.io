Una vez emitida, una factura o boleta no se puede editar. Para corregirla emites una **nota de crédito**, que anula o reduce el importe del comprobante (devoluciones, descuentos, errores), o una **nota de débito**, que lo aumenta (intereses por mora, penalidades).

Toda nota hace referencia al **comprobante afectado** e indica un **motivo** (el tipo de nota) y un **sustento** (una descripción del motivo). El resto de los campos son los mismos de una [factura](./01-invoices.mdx): proveedor, cliente y detalles.

## Nota de crédito

### Tipos de nota de crédito (Catálogo 9)

| Código | Motivo |
| ------ | ------ |
| `01` | Anulación de la operación (valor por defecto) |
| `02` | Anulación por error en el RUC |
| `03` | Corrección por error en la descripción |
| `04` | Descuento global |
| `05` | Descuento por ítem |
| `06` | Devolución total |
| `07` | Devolución por ítem |
| `08` | Bonificación |
| `09` | Disminución en el valor |
| `10` | Otros conceptos |

:::caution Nota de crédito tipo 13

La SUNAT define además el tipo `13` (ajuste de montos o fechas de pago), que exige informar cuotas. xhandler solo acepta los códigos `01` a `10` y la nota de crédito no tiene campo de forma de pago, así que este tipo no está soportado por ahora.

:::

### Tipos de nota de débito (Catálogo 10)

| Código | Motivo |
| ------ | ------ |
| `01` | Intereses por mora |
| `02` | Aumento en el valor (valor por defecto) |
| `03` | Penalidades u otros conceptos |

## Campos de la nota

| Campo | Java | Rust y Python | Go |
| ----- | ---- | ------------- | -- |
| Comprobante afectado | `comprobanteAfectadoSerieNumero` | `comprobante_afectado_serie_numero` | `ComprobanteAfectadoSerieNumero` |
| Tipo del comprobante afectado (Catálogo 1) | `comprobanteAfectadoTipo` | `comprobante_afectado_tipo` | `ComprobanteAfectadoTipo` |
| Tipo de nota (Catálogo 9 o 10) | `tipoNota` | `tipo_nota` | `TipoNota` |
| Sustento | `descripcionSustento` | `descripcion_sustento` | `DescripcionSustento` |

Valores por defecto cuando omites un campo:

- **Tipo de nota**: `01` (anulación de la operación) en la nota de crédito y `02` (aumento en el valor) en la nota de débito. Los valores por defecto son distintos, así que indica siempre el tipo para dejar claro el motivo.
- **Tipo del comprobante afectado**: se deduce de la **serie de la propia nota**. Una serie que empieza con `F` (por ejemplo `FC01`) da `01` (factura) y una que empieza con `B` (por ejemplo `BC01`) da `03` (boleta). Con cualquier otra serie el campo queda vacío, así que indícalo tú.

El tipo de nota es un texto con el código del catálogo. Un código que no existe hace fallar la creación del documento con un error de validación. En Rust también puedes usar el nombre de la variante (por ejemplo `"ANULACION_DE_LA_OPERACION"`), que se guarda como su código.

## Notas de boletas

Para corregir una boleta usa una serie que empiece con `B` (por ejemplo `BC01-1` o `BD01-1`), haz referencia a la boleta (`B001-1`) y usa el mismo cliente de la boleta, normalmente con DNI. La estructura es idéntica.
